# Planejamento anual dividido por Q

 O planejamento anual é organizado em **4 períodos de 3 meses**, chamados de **Q (Quarter)**:

- **Q1:** primeiros 3 meses do ano
- **Q2:** meses 4 a 6
- **Q3:** meses 7 a 9
- **Q4:** meses 10 a 12

Em cada **Q**, trabalhamos com duas etapas principais:

1. **Início do Q — Planejamento**
   - Definimos o que será estudado, desenvolvido ou realizado durante os próximos três meses.
   - Estabelecemos objetivos, atividades, entregas e resultados esperados.
2. **Final do Q — Avaliação e entrega**
   - Registramos o que foi realizado durante o período.
   - Verificamos o que ficou pendente.
   - Apresentamos as entregas realizadas.
   - Definimos o que será levado para o próximo Q.

Dessa forma, os quatro ciclos formam um **planejamento anual contínuo**, permitindo planejar, executar, avaliar e ajustar o trabalho ao longo do ano.

## Estrutura

| Período | Início | Durante | Final |
| --- | --- | --- | --- |
| **Q1** | Planejamento | Execução | Resultados e entregas |
| **Q2** | Planejamento | Execução | Resultados e entregas |
| **Q3** | Planejamento | Execução | Resultados e entregas |
| **Q4** | Planejamento | Execução | Resultados e entregas \+ fechamento anual |

**Em resumo:**

**Planejar → Executar → Avaliar → Entregar → Planejar o próximo Q**

Assim, o planejamento não é feito apenas uma vez no início do ano: ele é **revisitado a cada três meses**, permitindo ajustes conforme os resultados obtidos.

Esse modelo de planejamento por **Q** pode ser aplicado tanto em empresas quanto no **desenvolvimento pessoal e profissional**.

No caso de alguém que queira, por exemplo, **mudar de carreira para QA, DEV ou DevOps**, o planejamento trimestral ajuda a transformar um objetivo grande — que pode levar 1 ou 2 anos — em ciclos menores, concretos e avaliáveis.

## Exemplo: transição de carreira para tecnologia

Em vez de pensar:

> "Quero me tornar DevOps."

Podemos transformar isso em um **planejamento anual por Q**.

### Q1 — Fundamentos

**Objetivo:** construir a base necessária.

Estudar, por exemplo:

- Linux
- Redes
- Git e GitHub
- Shell/Bash
- Conceitos de desenvolvimento
- Fundamentos de cloud
- Inglês técnico

 **No final do Q1:**

- O que consegui aprender?
- Quais projetos consegui realizar?
- O que ainda não domino?
- O que será necessário estudar no Q2?

---

### Q2 — Desenvolvimento de habilidades

**Objetivo:** começar a transformar conhecimento em prática.

Por exemplo:

- Docker
- CI/CD
- GitHub Actions
- APIs
- Python
- Conceitos de infraestrutura
- Primeiros projetos práticos

**Entrega do Q2:**

Um ou mais projetos publicados no GitHub que demonstrem aquilo que foi aprendido.

---

### Q3 — Especialização e projetos

**Objetivo:** trabalhar com ferramentas e problemas mais próximos do mercado.

Por exemplo:

- Kubernetes
- Terraform
- AWS/Azure/GCP
- Observabilidade
- Segurança
- Automação
- Projeto de infraestrutura completo

Aqui o foco começa a mudar de **"estudar tecnologia"** para **"resolver problemas utilizando tecnologia"**.

---

### Q4 — Consolidação e entrada no mercado

**Objetivo:** transformar o conhecimento adquirido em algo profissional.

Por exemplo:

- Revisar os principais conhecimentos
- Melhorar os projetos do GitHub
- Montar portfólio
- Preparar currículo
- Preparar LinkedIn
- Simular entrevistas
- Fazer projetos de demonstração
- Identificar vagas compatíveis
- Começar a participar de processos seletivos

Ao final do ano, fazemos uma **retrospectiva anual**:

> O que eu planejei no início do ano?\
> O que efetivamente aprendi?\
> O que consegui construir?\
> Onde evoluí?\
> O que não consegui realizar?\
> O que precisa continuar no próximo ano?

## O ponto mais importante

Eu acho interessante não tratar o Q apenas como um **período de estudos**.

Ele pode representar um pequeno **ciclo de evolução**:

**Objetivo → Plano → Estudo → Prática → Projeto → Avaliação → Próximo objetivo**

Isso permite aplicar o mesmo método para diferentes objetivos:

- Aprender uma nova carreira
- Tornar-se DEV
- Tornar-se QA
- Tornar-se DevOps
- Aprender Cloud
- Aprender Python
- Melhorar o inglês
- Estudar para uma certificação
- Preparar-se para mudar de emprego

E há uma vantagem importante: **você não precisa saber exatamente onde estará daqui a 12 meses para começar**. Basta definir o próximo Q, executar, avaliar os resultados e usar o aprendizado para construir o planejamento do Q seguinte.

Esse conceito pode inclusive virar um **"Planejamento Pessoal por Q"**, com um modelo padrão para você preencher a cada trimestre.
